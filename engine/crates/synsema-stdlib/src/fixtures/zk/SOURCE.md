# `groth16_verify` test vectors

All of them produced by **snarkjs 0.7.6** (`npx -y snarkjs@0.7.6`, Node 24.14.0) on 2026-09-18,
with no hand edits: these are the files snarkjs writes, exactly as written (`include_str!` in
`zk.rs`). `snarkjs groth16 verify` answered `OK!` on every triple before it was copied here.

## `multiplier_*` — circom-compat `Multiplier` (a*b = c), nPublic = 1

From https://github.com/arkworks-rs/circom-compat, commit
`09e92d4c5887cec9ea558dc7e775a8ab3b02aafc`, directory `test-vectors/`:

- `mycircuit.circom` (`c <== a*b`), `mycircuit.r1cs`, `mycircuit_js/mycircuit.wasm`
- `test.zkey` (the repository's own zkey, generated by them with
  `snarkjs zkey new mycircuit.r1cs powersOfTau28_hez_final_17.ptau`)
- `verification_key.json` → **`multiplier_vk.json`** (byte for byte the one in the repository; it
  was also re-exported with `snarkjs zkey export verificationkey test.zkey vk.json` and all nine
  keys are identical)
- `mycircuit-input1.json` = `{"a": 3, "b": 11}`, `mycircuit-input2.json` = `{"a": r-2, "b": 11}`

Commands (in the directory holding those files):

    snarkjs wtns calculate mycircuit_js/mycircuit.wasm mycircuit-input1.json witness1.wtns
    snarkjs groth16 prove test.zkey witness1.wtns proof1.json public1.json   # → multiplier_proof_1 / multiplier_public_1 ("33")
    snarkjs wtns calculate mycircuit_js/mycircuit.wasm mycircuit-input2.json witness2.wtns
    snarkjs groth16 prove test.zkey witness2.wtns proof2.json public2.json   # → multiplier_proof_2 / multiplier_public_2 (r-2)*11 mod r
    snarkjs groth16 verify verification_key.json public1.json proof1.json    # OK!
    snarkjs groth16 verify verification_key.json public2.json proof2.json    # OK!
    snarkjs groth16 verify verification_key.json public2.json proof1.json    # ERROR Invalid proof (what the test expects too)

## `multiplier1000_*` — snarkjs `test/groth16` `Multiplier(1000)`, nPublic = 2

From https://github.com/iden3/snarkjs, commit `9a8f1c0083d18b9b5e18f526cfd729e7259423be`,
directory `test/groth16/`: `circuit.circom` (`component main {public [a]} = Multiplier(1000)`,
1000 constraints, one public input + one output), `circuit.r1cs`, `circuit.wasm`, `input.json`
(`{"a": 11, "b": 2}`) and `witness.wtns` (the repository's). There is no zkey in the repository, so
the ceremony was run here (the entropy is fixed and written below — this is a test fixture, not a
production ceremony):

    snarkjs powersoftau new bn128 11 pot11_0000.ptau
    snarkjs powersoftau contribute pot11_0000.ptau pot11_0001.ptau --name="synsema groth16 fixture" -e="synsema-groth16-fixture-entropy-2026-09-18"
    snarkjs powersoftau prepare phase2 pot11_0001.ptau pot11_final.ptau
    snarkjs groth16 setup circuit.r1cs pot11_final.ptau circuit_0000.zkey
    snarkjs zkey contribute circuit_0000.zkey circuit_final.zkey --name="synsema groth16 fixture" -e="synsema-groth16-zkey-entropy-2026-09-18"
    snarkjs zkey export verificationkey circuit_final.zkey verification_key.json   # → multiplier1000_vk.json
    snarkjs groth16 prove circuit_final.zkey witness.wtns proof.json public.json     # → multiplier1000_proof / multiplier1000_public
    snarkjs groth16 verify verification_key.json public.json proof.json              # OK!

`public.json` = `[c, a]` = `["19820469076730107577691234630797803937210158605698999776717232705083708883456", "11"]`
(snarkjs lists the outputs first and the public inputs after them).

## `plonk_vk.json` — negative vector

`snarkjs zkey export verificationkey test/circuit2/circuit.zkey` from the same iden3/snarkjs
commit: a real **PLONK** verification key (`protocol: "plonk"`). It pins that `groth16_verify`
rejects it for the protocol, with a clear error, rather than for its shape.
